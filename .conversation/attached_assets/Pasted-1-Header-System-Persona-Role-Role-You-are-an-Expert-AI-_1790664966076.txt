2. Core Mission Directive
Your mission is to develop an AI-Powered Agriculture Crop Advisory Assistant. This application must securely accept user inputs (text and image), interact with the new Google Gen AI SDK (@google/genai) to analyze crop data, store interactions securely in a PostgreSQL database, and present actionable, localized insights to farmers via a responsive, accessible React frontend.

3. Product Goal
Problem Statement: Farmers often struggle with crop diseases, unpredictable weather, and fluctuating market prices, which can lead to crop losses and reduced income.
Solution: An AI-powered farming assistant that detects crop diseases from uploaded images, provides localized weather-based farming alerts, and suggests optimal harvesting times and market selling strategies to maximize income.

4. Mandatory Features
Multimodal Disease Detection: Users can upload images of affected crops; the system uses Vision AI to identify diseases, assess severity, and provide treatment remedies.

Weather-Based Advisory: Contextual alerts based on user location and crop type to warn against frost, drought, or excessive rain.

Market Price & Timing Insights: AI-generated suggestions on the best time to harvest and sell specific crops based on simulated market trends and seasonality.

Historical Dashboard: A user-specific dashboard that tracks past scans, advisories, and saved insights.

Structured AI Outputs: All AI responses must be strictly validated against predefined JSON schemas.

Market Advisory: User requests selling advice for "Tomatoes in Maharashtra". The AI generates an economic advisory.

Review: User views the Dashboard to see a summary of weather alerts and past diagnoses.

10. Database Schema (Production SQL for PostgreSQL)
Execute the following schema to establish the database structure:

SQL
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    farm_location VARCHAR(255),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE disease_scans (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    crop_type VARCHAR(100) NOT NULL,
    disease_name VARCHAR(255) NOT NULL,
    confidence_score DECIMAL(5,2),
    remedy TEXT NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE market_advisories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    crop_type VARCHAR(100) NOT NULL,
    location VARCHAR(255) NOT NULL,
    advisory_content JSONB NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
11. Row Level Security (RLS) / Data Isolation Rules
Ensure that API endpoints strictly filter database queries by the authenticated user's user_id.

A user must never be able to GET, PUT, or DELETE records belonging to another user_id.
(Note: Implement logic at the Express controller level by appending WHERE user_id = $1 to all user-data queries).

12. Backend API Routes
GET /api/health - System health check.

POST /api/users/profile - Create/update user farm profile.

POST /api/ai/scan-disease - Middleware: Multer (memoryStorage). Takes image and crop type, calls Gemini API, saves to disease_scans, returns JSON.

POST /api/ai/market-advisory - Takes crop and location, calls Gemini API for market insights, saves to market_advisories, returns JSON.

GET /api/history/:userId - Fetches combined history from database.
